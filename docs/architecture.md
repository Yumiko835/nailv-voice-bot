# 架构、接口与限制

## 文字

输入→互动粗分→词义/行为召回24条表达→规划选行为0–2、表达0–3→身份骨架/事实/本轮范围/示范→原生Provider生成JSON。

reply显示给用户；delivery提供后台emotion/tone/pace/intensity/nonverbal；used_fact_ids只能引用本轮事实。表达示范不授权移植旧经历。原项目规划及nailv_provider._query显式temperature0.85、max_tokens1024，模型名通过.env配置。

正式AstrBot插件注入系统上下文并解析结果，不调用core.chat的早期自动重写。原生会话/工具结果仍属于AstrBot。部分旧页面代码及费用工具作为研究源码保留，并非新运行入口。

## 语音

本地live_bridge_server将文字、style、seed等交resident worker。GPT源声使用参考文本和音频，参考缓存deepcopy；SoVITS FP32解码、noise0.5。默认RP1.20/temp0.85/top_k5/top_p0.9。

D：32k源声→CV3前端Mel→官方HiFT→24k波形。默认没有CV3 LLM/Flow生成，也没有目标flow_embedding的第二次情绪表演。当前初始化/预热仍加载Flow及S3/CAMPPlus，所以文件需保留。HiFT重建可能改变颗粒和质感，不保证百分百保留情绪或无电音。

短句保留cut0上下文，长回复有界约64字thought分块；不逐逗号强拆。语义重复24触发有限重采样，16仅提示；不截token。静音收缩需能量/周期性确认，保护低声词。部分链路使用本地WAV交接，未实现完全零磁盘张量直通。

确认“嗯”仅对平静daily/explaining、明确句末、自然独立且约400–900ms的完整声段条件压到313ms，保留起收音；连音、思考、疑问、强情绪不强改，不自动给每句追加。不使用逐字CTC切音。

## QQ与服务

AstrBot插件只在自己bot、指定群且@或指定私聊范围工作；默认账号为空，需.env明确配置。生成失败回退文字。OneBot只绑定loopback，Token在本地。腾讯SILK成功编码仍不等于对端已播放，必须真人接收确认。

## 已知限制

- 原逗号E02在某些种子下仍可能长尾黏连，保护不强行切字。
- 没有已认可的纯净悲伤参考时，坚果话题只能用沉稳参考和克制文案兜底。
- ASR、声纹、F0与高频代理不是人评。不同文字F0不直接DTW，不因音高变化小就一概拒绝。
- 缓存与常驻提升热启动速度；冷启动和设备延迟没有统一保证。
- NapCat/QQ的会话可能失效，不能保证永久免扫码。某些Packet相关功能有限制。
- 部分源码是研究工具，需完整私有数据/阶段输入，不能直接拿空模板运行全部脚本。
- 本公开配置副本尚未通过新的GPU和QQ真人验收；CI只代表离线代码与公开包检查。
